# ADR-003 — Mark Sets (F-002)

## Contexto
Spec F-002; funcionalidade de Mark Sets, que consiste em copiar conteúdo de documentos de marca set pré-definidos para páginas alvo em um documento de destino. A evidência estática principal reside nas funções `0x18024D3E0`, `0x18024D460`, `0x18024E9B0` e `0x180251790` em `DocumentMarks.dll`. A evidência comportamental foi bloqueada por um diálogo de licenciamento (CAP-20261118-00).

## Decisão
A funcionalidade será implementada através de uma classe `MarkSetProcessor` em `src/prepress/markset_processor.h`, orquestrada por um módulo `MarksEngine`. Esta classe encapsulará a lógica de carregamento, processamento e aplicação das marcas, seguindo os contratos de geometria vetorial (`vector-geometry`).

## Mapeamento binário → ArtPlus
| Função (Ghidra) | Classe/método ArtPlus | Observação |
|---|---|---|
| 0x18024D3E0 | `MarkSetProcessor::applyMarksFromSet()` | Aplicação principal do conjunto de marcas. |
| 0x18024D460 | `MarkSetProcessor::identifyRelevantSets()` | Identifica conjuntos relevantes, envolve lógica de formas (`MakeFormsFromMarks`). |
| 0x18024E9B0 | `MarkSetProcessor::copyMarksToPage()` | Função de cópia de conteúdo de página para página. |
| 0x180251790 | `MarkSetProcessor::prepareMarksCachePage()` | Prepara o cache interno das marcas para a página alvo. |

## Contrato de interface (Proposto)
```cpp
class MarkSetProcessor {
public:
    // Estrutura para definir o conjunto de marcas a ser usado
    struct MarkSetConfig { 
        std::string sourceFilePath;
        std::string targetPageIdentifier; // Índice ou nome da página alvo
        bool useReuseStrategy = true; // Para critérios de relevância
    };
    
    // Carrega e processa o set de marcas
    bool process(const MarkSetConfig& config, Document& doc, size_t targetPageIndex) const;
    
private:
    // Métodos auxiliares mapeando as funções estáticas
    bool loadMarkSetFile(const std::string& path) const; // Mapeia 0x18024e460
    void generateMarksForms() const; // Mapeia lógica de 0x18024d460
};
```

## Consequências
- **Arquivos afetados:** Criação de `src/prepress/markset_processor.h`/`.cpp`.
- **Novos arquivos em `src/`:** `markset_processor.h`, `markset_processor.cpp`.
- **Dependências:** Dependência de `document-core` (Document, Page) e `vector-geometry`.
- **Risco:** Baixo, pois o mapeamento é baseado estritamente em assinaturas de função e na spec F-002.

## Alternativas descartadas
- Implementação direta em `Document` (viola princípio de responsabilidade; a lógica de *mark set* é transversal e deve ser isolada).
