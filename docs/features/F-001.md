# F-001 — Trim Marks (Cut Mark)

## 1. Resumo

Marca dinâmica de corte criada pelo painel `Marks` com o comando `Add Cut Mark`, sem diálogo
modal. É posicionada em relação a uma caixa de página (default observado: `Trim Box`) e
desenha linhas finas nos quatro cantos, prolongadas para fora dessa caixa. O objeto é
persistido no documento como `DynamicObject_PDFPlusCutMark` e reimportado pelo parser PDF+
com validação de `Orientation` e `Repetition`.

> Nomenclatura: a UI e o binário usam **Cut Mark**; o projeto rastreia a funcionalidade como
> **Trim Marks** (F-001). Não existe literal `Trim Marks` no binário.

## 2. Entrada

- **Documento:** PDF/PDF+ aberto no editor, com pelo menos uma página e as caixas de página
  definidas. Observado em `test_vector.pdf` (Media Box 210,00 × 297,00 mm, perfil
  `ISO Coated v2 300% (ECI)`, separações Cyan/Magenta/Yellow/Black/PANTONE 485 C).
- **Seleção:** nenhuma é necessária. O comando `Add Cut Mark` cria a marca direto na página
  corrente, independente de objeto selecionado.
- **Camadas:** nenhum requisito de camada observado. A marca é inserida no conteúdo da página
  (`InsertNewObjectOnTop`, `0x18013EE90`) e listada no painel `Marks`.
- **Pré-condições:** documento com `ArtDoc::Page` válida — `GetReferenceBox` exige
  `PageContent` para resolver `PageBox` (`0x18013CB50`). Sem conteúdo de página, a função
  devolve retângulo vazio.
- **Entrada de mark set:** marcas também entram na página pela cópia da primeira página de
  cada documento de mark set (`TaskMarkSets::ApplyMarksFromSet`, `0x18024D3E0`); esse caminho
  pertence a **F-002 — Mark Sets (a especificar)**, não a F-001.

## 3. UI

### Caminho

`Marks` (painel) → botão `+` / dropdown de criação → **`Add Cut Mark`**.

Itens irmãos no mesmo menu (contexto, não fazem parte desta spec): `Add Repeat for Grid Mark`,
`Add Bearer Bar Mark`, `Add Dimensions Mark`, `Add External File Mark`, `Add Position Mark`,
`Add Input File Mark`.

### Comportamento de criação

1. `Add Cut Mark` **não abre diálogo modal**. A marca é criada imediatamente.
2. O título da janela ganha `*` (documento alterado).
3. A barra de contexto passa a `Dynamic Marks | Cut Mark 1`.
4. A linha `Cut Mark 1` aparece no painel `Marks`.
5. Os parâmetros são editados depois, na barra `Dynamic Marks` / Inspector.

### Campos observados

| Campo | Tipo | Default | Unidade | Faixa / opções |
|---|---|---|---|---|
| `Attach to:` | dropdown + botão de alvo (crosshair) | `Trim Box` | — | `Media Box`, `Crop Box`, `Bleed Box`, `Trim Box`, `Art Box`, `Cut Mark 1` |
| offset | campo numérico + botão `fx` | `0,00 mm` | `mm` | não medida; exibição com 2 casas (resolução 0,01 mm) |

- O dropdown `Attach to:` lista as cinco caixas de página e a própria marca (`Cut Mark 1`),
  o que corresponde à referência por objeto (`GetReferenceBox` ramo `+0x780 == 1`).
- Com `Trim Box`, uma **guia vermelha** é desenhada sobre a borda do Trim Box.
- Atalhos: nenhum atalho de criação observado. `Ctrl+I` (`View > Open Next Inspector`) não
  abriu Inspector visível na sessão `CAP-20261119-01`; os campos foram lidos na barra
  `Dynamic Marks`.

## 4. Regras

### R1 — Criação direta, sem diálogo

`Add Cut Mark` cria o objeto e o insere na página corrente sem abrir modal. Efeito imediato:
entrada `Cut Mark N` no painel `Marks`, barra `Dynamic Marks | Cut Mark N`, título com `*`.
**Teste:** abrir documento, executar o comando → existe exatamente 1 nova marca no painel, 1
novo objeto de conteúdo na página, nenhuma janela modal.

### R2 — Defaults de fábrica do objeto

O construtor `PDFPlusCutMark::PDFPlusCutMark` (`0x18013A8B0`) grava:

| Campo | Valor default | Origem |
|---|---|---|
| `PageBox` (referência) | `3` | `this+0x708` |
| seletor de referência | `0` (PageBox) | `this+0x780` |
| referência por objeto/ID | `0` (nenhuma) | `this+0x788` |
| `Orientation` | `1` | `this+0x790` |
| `Repetition` | `2` | `this+0x794` |
| `LineTypes` | vetor com 1 elemento, valor `0` | `this+0x798` |
| `Offset` | coordenada `0`, seletor `0` (quantidade) | `this+0x698`, `+0x6B8` |
| tipo de cor | `setColorType(1, 0)` | chamada em `0x180098840` |

**Teste:** criar marca → offset exibido `0,00 mm`; `Attach to:` exibido `Trim Box`;
`Orientation`/`Repetition`/`LineTypes` iguais aos valores acima no objeto em memória.

> Inferência: `PageBox = 3` corresponde a `TrimBox` (fonte: `Document__GetPageBox.md`,
> confiança média — ordem canônica Media, Crop, Bleed, Trim, Art; o enum não tem nome no
> binário). A UI exibir `Trim Box` no default confirma o comportamento, mas não o índice.

> Inferência: `Orientation = 1` = `Vertical` (fonte: `0x18017C5D0`, que mapeia
> `"Horizontal" → 0` e `"Vertical" → 1`). Nenhum campo `Orientation` foi visto na UI.

### R3 — Resolução da caixa de referência

`GetReferenceBox` (`0x18013CB50`) resolve a caixa assim:

1. sem conteúdo → retângulo vazio;
2. seletor `PageBox` (`+0x780 == 0`) → `ArtDoc::Page::GetPageBox(page, PageBox)`
   (`Document.dll`, `0x1800FAE70`);
3. seletor objeto (`+0x780 == 1`) → `GetObjectWithID` + `GetPDFPlusBoundingBox`; objeto
   inexistente → retângulo vazio;
4. qualquer outro seletor → caminho de erro sem retorno (`FUN_180025A80`).

`GetPageBox` indexa o array de caixas pelo inteiro cru (stride `0x58`) e aplica a tabela de
fallback `DAT_1802EF6D8` quando a caixa não existe.

**Teste:** com `Attach to: Trim Box` e Trim Box = (x0, y0, x1, y1), as marcas usam exatamente
esse retângulo (tolerância ±0,01 mm); trocar para `Media Box` desloca a geometria para os
cantos da Media Box.

### R4 — Referência por objeto (`Cut Mark 1`)

Selecionar outra marca no dropdown grava a referência por ID
(`DocumentMarks_CutMark_ReferenceID`) e a resolução passa pelo ramo 3 de `GetReferenceBox`
(bounding box do objeto referenciado via `GetPDFPlusBoundingBox`).

**Teste:** duas marcas no documento; `Attach to: Cut Mark 1` na segunda → a segunda passa a
usar o bounding box da primeira; mover a primeira desloca a segunda na próxima regeneração.

> Inferência: mover a marca referenciada dispara regeneração da dependente (fonte:
> `SetCutMarkReferenceToAllStructuralDesignStations` `0x1800ADF00` e setters transacionais
> da classe; a propagação não foi capturada).

### R5 — Offset numérico (mm)

O offset é escrito por `SetCutMarkOffset` (`0x1800ADB10`), que monta getter/setter e executa a
alteração via `ArtDoc::ActionList::DoAction` — isto é, **toda edição de offset é uma ação
undoable**. O valor chega a `PDFPlusCutMark::SetOffset` (`0x18013D160`) como variant.

- Unidade de UI: `mm`, exibição com 2 casas (`0,00 mm`).
- Default: `0,00 mm` (coordenada 0).
- Faixa: não medida (ver Em aberto).

**Teste:** digitar `3,00` → `GetOffset` devolve coordenada equivalente a 3,00 mm; uma única
ação de undo retorna a `0,00 mm`.

> Inferência: offset positivo desloca as marcas **para fora** da caixa de referência e
> negativo para dentro (fonte: comportamento visual "projetadas para fora" com offset 0 e o
> nome `Offset` no posicionamento; o sentido não foi medido com offset ≠ 0).

### R6 — Offset por fórmula (`fx`)

O botão `fx` troca o offset numérico por uma fórmula textual. O variant aceita:

| Seletor `+0x6B8` | Conteúdo |
|---|---|
| `0xFF` | vazio (offset não definido) |
| `0` | `CoordinateBase<MilliPointCoordinateSystem,1>` (quantidade) |
| `1` | `std::string` (fórmula) |

A fórmula é resolvida na regeneração (`0x18013BDC0` a partir de `this+0x698`/`+0x6B8`). O
nome-base `PDFPlusCutMark_Offset` é lido em `getPositionRefBBox` (`0x18013ED6E`).

**Teste:** `fx` → digitar fórmula válida → offset resolvido e geometria regenerada; ação de
undo única reverte. Fórmula inválida → `RemoveInvalidCustomFormulasImp` (`0x18013CEF0`) a
remove via `SetCutMarkOffset`.

> Inferência: `PDFPlusCutMark_Offset` é o nome exposto da variável de offset para uso dentro
> da fórmula (fonte: `0x18013ED6E`; formato final da string não lido).

### R7 — Geração da geometria

`PDFPlusCutMark::regenerateMarkImp` (`0x18013EE90`, slot `[29]`):

1. apaga o conteúdo anterior da marca (`DocumentEdit::Delete`);
2. resolve o offset (quantidade ou fórmula);
3. obtém a caixa de referência por `GetReferenceBox` (`0x18013FFE4`);
4. aplica cor (`ApplyPDFPlusColor`) e bounding box (`GetPDFPlusBoundingBox`);
5. calcula orientação com `cos`/`sin`/`atan2`;
6. insere os objetos com `InsertNewObjectOnTop`, dentro de
   `ActionGroupCreator`/`Expander` (transação de undo).

Saída visual observada (`CAP-20261119-01`): linhas finas rosadas/vermelhas em cada canto da
caixa de referência, paralelas às bordas e prolongadas para fora do Trim Box; moldura laranja
da página e guia vermelha da borda do Trim Box são chrome de visualização.

**Teste:** criar marca em página 210 × 297 mm com Trim Box = Media Box → existe **1
`GroupObject` com 8 `PathObject`** (4 vértices × 2 segmentos), todo traço de marca fica fora do
interior da caixa (a menos do cruzamento no vértice), nenhuma marca dentro da área de arte;
coordenadas dos segmentos conferidas contra tabela independente com tolerância de posição
**±0,03 pt**. Undo único remove a geometria inteira (o grupo).

> Inferência: 1 grupo com 8 paths (4 vértices × 2 segmentos), conforme `ADR-001` D3 e
> `src/prepress/cut_mark.cpp` (fonte: `crop-corner-tl.png` e `crop-corner-br.png` confirmam 2
> vértices; simetria e o nome "Cut Mark" sustentam os outros 2). Comprimento, espessura e
> paridade exata com o original não foram medidos.

### R8 — Regeneração por mudança de parâmetro

Alterar `Attach to:`, offset (número ou fórmula), `Orientation`, `Repetition` ou `LineTypes`
leva a nova execução de `regenerateMarkImp`: o conteúdo anterior é apagado e recriado, em uma
única transação. Setters transacionais: `SetCutMarkOffset` `0x1800ADB10`/`0x1800AD910`,
`SetCutMarkOrientation` `0x1800ADCA0`/`0x1800ADE00`, `SetCutMarkRepetition`
`0x1800AE100`/`0x1800AE260`, `SetCutMarkLineTypes` `0x1800AD540`/`0x1800AD730`.

**Teste:** alterar `Attach to:` de `Trim Box` para `Bleed Box` → geometria nos vértices da
Bleed Box; contagem de objetos de conteúdo da marca não cresce (regeneração substitui, não
acumula).

### R9 — Identidade e nome do objeto

- Tipo persistido: `getMarkType()` (`0x18013E3B0`) devolve
  `DynamicObject_PDFPlusCutMark`.
- Nome exibido: `Cut Mark N` (`Cut Mark 1` na primeira criação).
- Hierarquia: `ContentObject` → `Group` → `DynamicObject` → `DynamicMark` → `PDFPlusCutMark`;
  interfaces `Visitable` e `ArtDoc::Detail::ListItem<ContentObject>`.

**Teste:** após criar a primeira marca, o painel `Marks` mostra `Cut Mark 1` e o objeto
serializa com tipo `DynamicObject_PDFPlusCutMark`.

> Inferência: a numeração `N` é sequencial por documento e reinicia por documento (fonte:
> única observação `Cut Mark 1`; sequência não testada com 2+ marcas).

### R10 — Persistência no PDF+ (escrita)

A marca é gravada como objeto dinâmico PDF+ com:

| Chave | Papel | Evidência |
|---|---|---|
| `DynamicObject_PDFPlusCutMark` | tipo do objeto | `0x180312B40` |
| `Position` | sub-dicionário de posicionamento | parser `0x18017C5D0` |
| `Reference` | referência (`PageBox` ou `AllStructuralDesignStations`) | parser `0x18017C5D0` |
| `Orientation` | `Horizontal` = 0, `Vertical` = 1 | parser `0x18017C5D0` |
| `Repetition` | 0, 1 ou estado estendido (`2` no ctor) | parser `0x18017C5D0` |
| `LineTypes` | vetor de tipos de linha (default `[0]`) | ctor + parser |
| `PDFPlusCutMark_Offset` | nome do offset para fórmula | `0x180323368` |
| `DocumentMarks_CutMark_ReferenceID` | ID da referência por objeto | `0x180326A08` |
| `PDFPlusCutMark_OriginalReferenceName` | nome original da referência | `0x180323180` |

**Teste:** salvar e reabrir → marca reimportada com mesmo `Attach to:`, offset e geometria;
as chaves acima presentes no dicionário da marca.

> A serialização de saída **não foi verificada**: `Save As` falhou na captura
> (`O nome do arquivo não é válido.`) e nenhum PDF de saída foi gerado. Ver Em aberto.

### R11 — Importação PDF+ e validação

`FUN_180172550` (leitor de marca PDF+, ~105 KB) constrói `PDFPlusCutMark` com o `FormPaint`
do símbolo em `0x1801747BA` e chama o parser `FUN_18017C5D0`:

1. lê o sub-dicionário `Position` (`GADict::GetDict`) → `FUN_1801861F0`;
2. lê `Reference` (`GADict::GetName`); se `AllStructuralDesignStations`, exige
   `Orientation`, `Repetition` e `LineTypes`, senão lança exceção C++ sem mensagem textual;
3. `Orientation`: `Horizontal` → 0, `Vertical` → 1; qualquer outro → exceção
   `Cut Mark has invalid Orientation value` (`0x180327538`);
4. `Repetition`: aceita 3 estados; fora do contrato → exceção
   `Cut Mark has invalid Repetition value` (`0x180327560`);
5. aplica `SetReferenceObject`, `SetOrientation`, `SetRepetition`, `SetOffset`
   (`0x18013D160`, em 3 pontos).

**Teste (unidade, sobre o parser):** dicionário com `Orientation = "Horizontal"` → objeto com
`Orientation = 0`; com `"Vertical"` → `1`; com `"Diagonal"` → exceção com a mensagem literal;
`Reference = "AllStructuralDesignStations"` sem `LineTypes` → exceção.

### R12 — Caminho legado (AI Dynamic Marks)

Documento/mark set com `AIDynamicMarks-CutMark`:

1. `createDynamicObject` (`0x180111410`) compara o nome via `memcmp` (len `0x16`) em
   `0x1801122FE` e chama `CutMark::CutMark(true)` (`0x180052340`) em `0x18011235D`;
2. `CutMark::parsePdfPropertiesDict` (`0x180052A50`) lê o dicionário `DM-CutMarkParams` com
   `-Offset`, `-SymbolDefinition`, `-Version`;
3. `CutMark::regenerateMarkImp` (`0x180052CA0`) obtém o bounding box de referência
   (`getPositionRefBBox`), clona o símbolo (`CloneStrategy`), insere depois da marca
   (`InsertNewObjectAfter`) e posiciona com `PlaceCutMarkSymbol` (`0x180052820`, `CPoint` ×2);
4. com nível de debug > 2, imprime ` Cut Mark update at \n` (`0x180308DF0`).

Diferença estrutural: o caminho legado **posiciona cópias do símbolo**; o caminho PDF+ gera
a geometria diretamente.

**Teste:** importar mark set legado com `AIDynamicMarks-CutMark` e
`DM-CutMarkParams-Offset` → objeto `CutMark` criado, offset aplicado, símbolo clonado nos
cantos.

> Inferência: o número de cópias do símbolo é 4 (um por canto) (fonte: `0x180052CA0`; a
> contagem depende de `dm::CutMarkPositionGenerator`, cujo vetor de posições não foi contado).

### R13 — Aplicação por mark set (F-002 — Mark Sets)

`TaskMarkSets::ApplyMarksFromSet` (`0x18024D3E0`) percorre os documentos do mark set, pega a
**primeira página** de cada um e copia o conteúdo para a página alvo
(`CopyMarksToPageWithLog`, `0x18024E9B0`). `ApplyRelevantMarkSets` (`0x18024D460`) complementa
com separações e `MakeFormsFromMarks`.

Esse fluxo **não pertence a F-001**: fica registrado como **F-002 — Mark Sets (a especificar)**.
Não existe `docs/features/F-002.md` nem entrada no índice de features enquanto a spec não for
escrita. F-001 cobre apenas a marca criada/editada na página; a entrada por mark set é
dependência de F-002.

**Teste:** não aplicável em F-001. A spec F-002 deve provar: mark set com 1 documento de 1
página contendo Cut Mark → aplicar na página alvo gera uma cópia da marca, com o mesmo tipo e
parâmetros.

## 5. Exceções

| # | Condição | Comportamento | Evidência |
|---|---|---|---|
| E1 | `Orientation` fora de `Horizontal`/`Vertical` | exceção `Cut Mark has invalid Orientation value` | `0x18017C5D0` / `0x180327538` |
| E2 | `Repetition` fora dos 3 estados | exceção `Cut Mark has invalid Repetition value` | `0x18017C5D0` / `0x180327560` |
| E3 | `Reference = AllStructuralDesignStations` sem `Orientation`, `Repetition` ou `LineTypes` | exceção C++ sem mensagem textual | `0x18017C5D0` |
| E4 | Fórmula de offset inválida | fórmula removida via `RemoveInvalidCustomFormulasImp` (`0x18013CEF0` → `SetCutMarkOffset`) | `0x18013CEF0` |
| E5 | Objeto de referência inexistente | `GetReferenceBox` devolve retângulo vazio → marca sem caixa | `0x18013CB50` |
| E6 | Página sem conteúdo (`PageContent` ausente) | `GetReferenceBox` devolve retângulo vazio | `0x18013CB50` |
| E7 | Caixa de referência ausente na página | `GetPageBox` usa a tabela de fallback `DAT_1802EF6D8` (caixa substituta não identificada) | `Document__GetPageBox.md` |
| E8 | Seletor de referência desconhecido | caminho de erro sem retorno (`FUN_180025A80`) | `0x18013CB50` |
| E9 | Documento sem página / comando sem página corrente | não observado; sem evidência de mensagem | lacuna |

- E1 e E2 não foram reproduzidos na UI (`CAP-20261119-01`): nenhum campo `Orientation` ou
  `Repetition` apareceu no inspetor/barra. A especificação cobre o parser, não a mensagem de
  UI.
- A falha `O nome do arquivo não é válido.` no `Save As` é artefato da sessão de captura, não
  é comportamento da marca; está registrada em Em aberto.

## 6. Saída

**No documento (persistente):**

- um objeto de conteúdo `PDFPlusCutMark` inserido no topo do conteúdo da página
  (`InsertNewObjectOnTop`), dentro de uma transação de undo;
- 8 segmentos de marca (4 vértices × 2) em um único `GroupObject`, prolongados para fora da
  caixa de referência;
- entrada `Cut Mark N` no painel `Marks`;
- documento marcado como alterado (`*` no título).

**No arquivo PDF/PDF+ (persistente):**

- dicionário da marca com tipo `DynamicObject_PDFPlusCutMark`, `Position`, `Reference`,
  `Orientation`, `Repetition`, `LineTypes`, `PDFPlusCutMark_Offset`,
  `DocumentMarks_CutMark_ReferenceID`, `PDFPlusCutMark_OriginalReferenceName`
  (chaves observadas; conteúdo exato por chave é lacuna);
- no caminho legado, dicionário `DM-CutMarkParams` com `-Offset`, `-SymbolDefinition`,
  `-Version`.

**Só visual (não gravado no PDF):**

- moldura laranja da página/Media Box;
- guia vermelha sobre a borda do Trim Box (indicação de `Attach to`);
- rótulo `Media Box 210,00 x 297,00 mm` e demais rótulos do visualizador;
- seleção/handles da marca.

**Fora do escopo de saída:** separações e `Document Profile` do documento não são alterados
pela criação da marca (nenhuma escrita em separações observada no fluxo de criação).
